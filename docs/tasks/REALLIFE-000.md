# REALLIFE-000 — настройка репозитория и обнаружение Unity

## Цель

Подготовить существующий локальный checkout репозитория https://github.com/kpCat/RealLife.git к разработке. Работать в папке, уже открытой владельцем в Codex. Эта задача не создаёт Unity-проект, игровой код, сцены или тестовые копии.

## 1. Git и рабочая папка

- Определить фактический корень существующего checkout, состояние Git, текущую ветку и remote. Использовать установленный Git.
- Убедиться, что origin указывает на kpCat/RealLife (HTTPS либо корректный уже настроенный SSH). Удалить только ошибочную настройку собственного origin при необходимости, не менять остальные репозитории и не перенастраивать глобальный Git.
- Получить актуальные удалённые refs. Основная ветка — main; использовать существующую историю, не выполнять git init поверх клона, не переписывать историю и не делать force push. Если удалённая версия изменилась, аккуратно согласовать её с локальными файлами, не уничтожая чужие изменения. При действительно неоднозначном конфликте остановиться и сообщить.
- Проверить существующую безопасную авторизацию Git (Credential Manager, уже настроенный SSH и т.п.) без раскрытия секретов. При необходимости только пользователь выполняет обязательный интерактивный вход. Не сохранять токены в репозитории или README. Фактическая возможность push подтверждается настоящим push, а не предположением.

## 2. Файлы проекта

Проверить подготовленные README.md, AGENTS.md, .gitignore, .gitattributes и docs/. AGENTS.md находится в корне именно этого проекта. Глобальные инструкции Codex не менять. Обновить прежний пустой README содержательным README из пакета; не заявлять несуществующую игру, выпуски, скриншоты или лицензию.

Проверить .gitignore на типичных путях будущего Unity-проекта: Library/, Temp/, Obj/, Logs/, UserSettings/, Builds/, выгрузки, диагностика, сейвы, локальные геопакеты, IDE и секреты должны игнорироваться; Assets/, Packages/, ProjectSettings/, .meta, исходники и документация должны оставаться доступными для Git. Не создавать настоящие огромные артефакты ради проверки: git check-ignore на пути достаточно.

Исследования — подчинённая справочная база. В публичный Git помещать только разрешённые тексты и собственные исходники. Не добавлять приватные сведения, реальные токены, локальные конфиденциальные настройки и сырьё с ограничениями распространения. Не устанавливать Git LFS и не загружать бинарные наборы на этом шаге без необходимости.

## 3. Найти установленную Unity

Без установки большого нового SDK и без полного сканирования всех дисков в первую очередь изучить Unity Hub и его настройки/список редакторов, известные пути Unity Hub/Editor, стандартные директории Program Files, записи установленных программ и известные пользовательские директории на диске D:. Найти фактические Unity.exe и подтвердить версии/путь по надежным метаданным редактора. Определить наличие Windows x64 Build Support (Mono; IL2CPP опционально). Не удалять существующие версии и не менять лицензию или глобальные настройки. Если найден подходящий стабильный редактор Unity 6.x LTS, рекомендовать его, предпочтительно совместимый 6.3 LTS. Если установлен другой редактор, указать реальную версию и совместимость, не делать слепой апгрейд. Если редактор не найден/нужна активация, честно сообщить, что именно требуется. Отсутствие Unity не мешает опубликовать документацию и Git-настройки.

## 4. Коммит и публикация

Разумно обновить README/документацию по фактическому результату, без абсолютных локальных путей или приватных сведений в публичных документах. Проверить git status и staged diff; добавить только нужные файлы. Сделать нормальный коммит с осмысленным сообщением (например, "Initialize RealLife project documentation and repository"), затем push в origin/main. После push сверить фактический локальный HEAD с удалённым HEAD main. Не использовать ветки разработки, worktree, новый clone, отдельные проекты или временный репозиторий.

## Завершение

Краткий отчёт на русском:
- путь к существующему репозиторию, origin, ветка main;
- SHA коммита, ссылка на GitHub и подтверждение remote HEAD;
- что опубликовано; проверка игнорирования мусора;
- обнаруженные версии Unity, фактический локальный путь к выбранному Unity.exe, наличие нужных модулей и что мешает следующей задаче, если мешает.

Не просить владельца запускать тесты. Не устанавливать Unity заново только ради этой задачи. Не приступать к REALLIFE-001, до следующего задания. Это подготовка, а не играбельный выпуск.
